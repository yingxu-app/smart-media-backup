UPDATE & ROLLBACK

更新与回退

偏好设置里的“检查更新”查询正式版本后，可直接下载并校验对应安装包的 SHA-256。影序不会覆盖正在运行的应用；下载完成后仍需按系统步骤手动安装。

更新前先保护备份记录

  1. 等当前备份任务结束，退出影序。
  2. 在偏好设置点击“检查更新”，再点击“下载并校验安装包”。影序会从 GitHub 最新正式发行版下载适用于当前系统的文件，并在交给浏览器前校验 GitHub 提供的 SHA-256。
  3. 也可以从影序的 GitHub 正式发行页手动下载。手动下载时请按下载页说明自行计算 SHA-256，并与同版本 SHA256SUMS.txt 比对。
  4. 把用户数据目录复制到安全位置作为回退副本。默认目录为 macOS/Linux 的 ~/.config/smb/，Windows 的 %USERPROFILE%\.config\smb\。里面包含备份历史、设置，也可能有第三方服务凭据；请只保存在你控制的本机或加密磁盘，不要上传或发给他人。

安装新版本

macOS

  1. 退出影序，把当前 影序 YINGXU.app 复制一份并改名标记旧版本，放在应用程序文件夹以外的位置。
  2. 打开已校验的 DMG，把新 App 拖到“应用程序”，按 Finder 提示替换旧版本。
  3. 按当前决策，后续发行版不配置 Developer ID 身份签名和 Apple 公证。macOS arm64 构建仍使用无开发者身份的 ad-hoc 技术签名，以满足 Apple Silicon 的代码签名加载要求；它不验证发布者身份。macOS 可能显示无法验证开发者或无法检查恶意软件的警告；只有在确认文件来自官方发行页且 SHA-256 匹配后，才考虑按 Apple 的安全打开说明自行决定是否允许打开。若系统提示已检测到恶意软件或应用已损坏，请停止安装，不要绕过该提示。

Windows

按当前决策，后续 Windows 发行包不做代码签名，系统可能显示发布者未知或安全警告。先从官方发行页下载并核对 SHA-256；只要校验不一致或来源不确定，就不要运行。

  1. 退出影序，保留旧版本文件夹不动。
  2. 把新发行包解压到一个新的版本文件夹，先核对 EXE 的 SHA-256，再从该文件夹启动新版本。不要在旧程序仍运行时覆盖 EXE。
  3. 确认新版本能启动并正确显示历史后，再自行决定是否清理旧程序副本；不要删除用户数据目录。

回退到旧版本

  1. 退出当前版本。macOS 启动保留的旧 App；Windows 从保留的旧版本文件夹启动原 EXE。
  2. 如果旧版本无法读取升级后的历史数据库，先把当前 .config/smb 文件夹改名保留，再将更新前的安全副本恢复到原位置，然后启动旧版本。
  3. 回退后暂时停止新的备份写入，保留问题版本、旧版本和两份数据目录，直到确认历史完整。

回退副本只在更新前创建时才能恢复到更新前的数据状态。影序不会自动删除旧程序或自动回滚用户数据。

自动校验只确认下载包与 GitHub 正式发行元数据中的 SHA-256 一致，不会安装或替换当前应用。官方版本、安装包与校验文件以 GitHub 最新正式发行页为准。返回下载页
