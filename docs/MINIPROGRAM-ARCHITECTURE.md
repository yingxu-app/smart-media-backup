# 影序微信小程序联通方案

日期：2026-10-16。此文用于决定真实联通架构，不代表小程序源码、服务端或上架已经完成。

## 官方网络约束

微信小程序网络文档说明：

- 小程序网络 API 与配置过的服务域名通信；基础库 2.4.0 起支持访问局域网 IP，但不支持访问运行小程序的本机 IP。
- 普通服务器域名需按接口配置；`wx.request` 等使用 HTTPS，WebSocket 使用 WSS。HTTPS 证书需要有效、受系统信任、主机名匹配且证书链完整；自签名证书不适用于 iOS。
- `wx.createTCPSocket`（基础库 2.18.0 起）允许连接同一局域网内的非本机 IP，但有禁用端口列表和每 5 分钟最多创建 20 个 socket 等限制。
- 微信云托管可使用 `callContainer` 与 `connectContainer`，通过微信私有协议发起 HTTPS 与 WebSocket 请求，可不配置普通通信域名。

参考：

- [微信小程序网络使用说明](https://developers.weixin.qq.com/miniprogram/dev/framework/ability/network.html)
- [微信云托管 callContainer](https://developers.weixin.qq.com/miniprogram/dev/wxcloudservice/wxcloudrun/src/development/call/mini)
- [微信云托管 connectContainer](https://developers.weixin.qq.com/miniprogram/dev/wxcloudservice/wxcloudrun/src/development/websocket/miniprogram)

## 与影序现状的差异

影序 Pocket 当前由桌面端提供局域网 HTTP 页面与 API，默认服务端口为 8080。浏览器可直接访问，但 8080 落在微信 TCP API 的禁用端口范围 8000–8100 内；因此现有 Pocket HTTP 端口不能直接用于小程序 TCP 连接。开发者工具的跳过域名/证书检查仅适合开发调试，不能作为生产网络配置。

## 候选实现：同一局域网 TCP 直连（待用户选择与真机验证）

已安装的微信开发者工具 36.6.0 所带 `wx-snippets` API 文档说明：`wx.createTCPSocket` 自基础库 2.18.0 可用，允许连接同一局域网内的非本机 IP；端口 `8000–8100`（含影序当前默认 `8080`）被禁止，且每 5 分钟最多创建 20 个 socket。对应官方 API 页面见上方链接。此证据来自本机开发者工具随附的 API 文档，尚不等于 iPhone/Android 真机联通验收。

这提供了不经云端的候选路径：桌面端在用户主动开启 Pocket 时，另开一个高位 TCP 端口（初选 `18080`，仍需真机确认）并只开放配对、状态、用户请求的历史摘要和拍摄备注。照片/视频、原始本地路径、桌面设置及备份控制命令不进入该接口。配对码短期单次有效，会话可撤销；监听默认关闭。由于直接 TCP 没有 TLS，本路线需限制在同一局域网并审查协议认证、重放保护和最少数据暴露，不能把监听端口暴露到公网。

## 可选实现：微信云托管中继（远程协作）

保持桌面备份完全本地运行；用户主动启用“小程序远程协作”后，桌面端建立向云托管发起的出站 TLS/WebSocket 连接，小程序通过微信云托管 API 与桌面端会话通信。云端只中继必要的协作数据：

- 一次性配对码、短期会话票据和设备在线状态；
- 当前备份进度、用户主动请求的历史摘要；
- 小程序用户明确提交的拍摄备注。

默认禁止中继照片/视频字节、原始本地路径、访问令牌、桌面设置和备份控制命令；后续若要增加控制能力，另行设计授权、重放保护和审计。没有启用远程协作时，桌面端不建立该连接。必须提供断开/撤销、会话过期和数据删除路径。

## 可选方案：备案域名 HTTPS/WSS

也可为小程序配置自有服务器域名与可信证书，再通过带 TLS 的受限 API 联通桌面服务。这需要可公网访问的服务入口、备案域名、证书续期、账号后台配置和网络安全审计；将局域网服务暴露到公网还需独立威胁审查，不应直接转发桌面工作台端口。

## 需要用户决定与参与

1. 确认小程序按微信平台推进（目前只按此假设整理方案）。
2. 选择正式连接路径：当前分支已按同一局域网 TCP 直连做默认关闭的候选实现（不经过云端）；也可改为微信云托管中继（支持远程，但会增加云端数据路径）或备案域名 HTTPS/WSS。公开发布前需要确认数据路径。
3. 准备正式小程序 AppID 和微信公众平台开发权限；AppID 可用于项目配置，但不得提供 AppSecret、密码或登录验证码。
4. 若选择云托管，创建/指定 CloudBase 或微信云托管环境，并在官方控制台完成账号绑定、隐私声明与域名/环境配置。

## 交付门禁

- 项目包含正式 `app.json`、页面、分包/权限配置和可重复构建命令；使用真实 AppID 构建。
- 后端只返回明确授权的最少数据；配对码单次有效且短期过期，会话可撤销，敏感值不进入日志。
- 使用开发者工具关闭域名/证书绕过后验证；至少在真实 iPhone 与 Android 微信完成配对、前后台切换、网络切换、历史和备注验收。
- 完成微信隐私保护指引、用户授权、审核、正式提交和线上版本检查后，才声明上架完成。

## v1.0.39 候选实现状态（2026-10-16）

- 主仓库新增 `miniprogram/`，包括小程序页面、TCP 客户端和占位 `project.config.json`；该工程使用 `touristappid`，仅供代码结构验证，不是可提交审核的真实 AppID。
- 桌面端新增 `pocket_tcp_enabled` 配置，默认关闭；用户可在偏好设置显式开启专用 TCP 监听 `18080`。桥只接受配对、状态、历史摘要、拍摄备注和断开操作，不读取照片/视频、不返回绝对路径、不提供备份控制。
- 原型协议使用单条长连接和 URL 编码 JSON 行，限制 8 个并发连接、每来源 10 分钟 5 次错误配对；配对后复用短期会话令牌。原型没有 TLS，因此只允许用户主动在可信局域网启用。
- 5 项 `tests/test_pocket_tcp.py` 通过；小程序 JS 与 JSON 语法检查通过。微信开发者工具 CLI 打开项目时返回 `AppID 不存在 (code 10)`，尚未成功预览。未做真机、端口防火墙、AppID 隐私配置或发布验收。
- 正式路线选择仍待用户确认；公开发布门槛包括真实 AppID、开发者工具编译、iPhone 与 Android 微信同 Wi-Fi 实测、前后台/网络切换、权限与隐私审查和微信审核上架。

因此当前已有客户端和桌面桥接原型，但微信小程序尚未完成真机或生产验收。
