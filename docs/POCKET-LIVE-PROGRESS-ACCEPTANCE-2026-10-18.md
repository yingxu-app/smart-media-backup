# Pocket 实机备份进度验收（2026-10-18）

## 范围与环境

真实 iPhone，通过 iPhone Mirroring 操作已添加到主屏幕的 Pocket 网页 App；连接本机安装的影序 v1.0.40 局域网服务。此修正为本机候选，未发布正式版。

测试根目录为项目外层 `验收记录/2026-10-18-Pocket实时进度/`。合成 BMP 图片 80 个，共 62,918,880 字节。来源独立；每轮使用独立目标。云盘未授权、Webhook 未配置。临时限速设置在任务终态后恢复为 0。

## 发现与修正

- 原手机页面复制到 24/80、51/80 时仍显示 100%。原因是读取元数据阶段遗留 `phase_progress=100`；复制/暂停时改按复制加跳过文件数计算比例。
- 原速度字段从未在复制循环赋值。改以单文件复制、校验及限速耗时计算实际吞吐；失败不计入成功复制字节。
- 每次任务重置进度与限速窗口，保留观察回调，防止下一次任务继承上一轮计数。
- 历史 API 使用 `completed`，手机只识别 `done`，导致已完成任务显示待处理。增加 completed 映射。
- 完成时速度归零，当前文件提示改成备份已完成或部分完成。

## 已核实证据

- 原包：手机实时计数从 24/80 增至 51/80，终态显示备份已完成、80/80。

## 构建踩坑

- venv 的 pyinstaller 启动脚本残留旧目录 shebang，使用 `.venv/bin/python -m PyInstaller`。
- 中途修改源码后复用构建缓存，PYZ 未包含最后的完成提示。通过读取 PYZ 的 smb.backup 代码常量发现不匹配；最终改为 `--clean`、全新 build/dist 目录，再核验包内代码。
- 替换包之前必须确认旧进程已完全退出、8080 无监听；仅操作退出按钮后立即启动可能沿用旧进程。

## 最终清理重建结果

- clean 包的 PYZ `smb.backup` 中已核验包含“备份已完成”常量；已安装并重启，确认新进程提供服务。
- 对同一目标再次执行增量备份，服务端结果：copied=0、skipped=80、verified=80、failed=0、status=done、current_speed=0、current_file=备份已完成。
